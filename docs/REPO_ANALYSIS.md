# Разбор чужих репозиториев — задания для агента

Цель: для каждого проекта понять, **как он работает** и **что мы забираем себе** (идею, алгоритм, описание эндпоинта, UX-решение), а что нет. Результат каждого задания — отдельный отчёт в `docs/research/<owner>__<repo>.md` по шаблону ниже. После всех отчётов — сводка `docs/research/SUMMARY.md` и обновление `docs/MARKETS.md`.

## 0. Правила разбора (читать до начала)

- **Только чтение.** Смотрим исходники через GitHub (веб, `gh api repos/<o>/<r>/contents/...`, raw-файлы). Ничего не запускаем, не ставим зависимости, не скачиваем релизы.
- **Подозрительные репо** (см. §3) — читать только README и структуру, исходники открывать как текст. Отметить признаки малвари в отчёте.
- Код не копируем в проект. В отчёт можно вставлять короткие фрагменты (до ~20 строк) с указанием файла и строки, чтобы показать алгоритм.
- Фиксировать лицензию и дату последнего коммита: это влияет на то, можно ли опираться на проект.
- Если что-то не удалось прочитать — так и написать в отчёте, не додумывать.

## 2. Задания по репозиториям

### A. topcvetok/telegram-gift-watch — приоритет 1
https://github.com/topcvetok/telegram-gift-watch
Мониторинг Tonnel, Portals, MRKT с уведомлениями. Сам не покупает.

Изучить:
1. Как считается флор по коллекции, модели и фону; минимальное число сопоставимых; что считается «слишком разбросанными» ценами.
2. Правило «≥15% ниже флора и ≥5 соседних объявлений» — где в коде, какие параметры.
3. Проверка медианой продаж за 24 часа: откуда берутся продажи на каждом маркете.
4. «Красивые номера» (разные цифры) и монохром (внешний калькулятор Clue) — алгоритм и можно ли посчитать монохром самим по цвету фона/модели.
5. Tonnel: WebSocket событий — адрес, формат сообщений, обход защиты (что именно имитируется).
6. Portals: какие публичные маршруты без авторизации, частота 5 с.
7. MRKT: `/api/v1/feed`, `/api/v1/gifts/saling` — формат.
8. Антидубли уведомлений и замена сообщения на «ПРОДАНО».
9. Кэширование флоров (15/30 мин) и SQLite-чекпоинты.

Забираем: логику флора и фильтров → `pricing/`, `rules/`; формат событий Tonnel → `markets/tonnel.py`; идею «SOLD»-обновления пуша → `bot/`.

### B. bleach-hub/portalsmp (+ aportalsmp) — приоритет 1
https://github.com/bleach-hub/portalsmp — архивирован, используем как справочник.

Изучить:
1. Полный список эндпоинтов: search (все фильтры и сортировки), giftsFloors, filterFloors, collections, marketActivity, myActivity, buy, sale, bulkList, changePrice, offers, collectionOffers, withdraw, balances.
2. Формат `authData` (`tma ...`), как `update_auth()` получает initData через Pyrogram, срок жизни.
3. Формат цен (строка/число, точность), как передаётся цена в buy.
4. Найти async-версию aportalsmp: отличия, живая ли.

Забираем: схему эндпоинтов → `docs/MARKETS.md#portals`, затем свой клиент `markets/portals.py`.

### C. bleach-hub/tonnelmp — приоритет 1
https://github.com/bleach-hub/tonnelmp

Изучить: эндпоинты поиска, покупки (`transferGift`, внутренняя покупка), продажи, баланса; поля подарка (`gift_num`, `gift_id`, `model`, `backdrop`, `symbol`, `price` без 10% комиссии); как обходится защита (заголовки, TLS-отпечаток).
Сверить с **boostNT/Tonnel-API**.

Забираем: схему → `docs/MARKETS.md#tonnel`, клиент `markets/tonnel.py`. Важно: цена в API без 10% комиссии покупки.

### D. amrkt (thebrainair/amrkt) + boostNT/MRKT-API + tgmrkt-api — приоритет 1
https://github.com/thebrainair/amrkt · https://github.com/boostNT/MRKT-API · https://pypi.org/project/tgmrkt-api/

Изучить:
1. Авторизация: `POST https://api.tgmrkt.io/api/v1/auth {"data": initData}` → token; заголовки (`Referer`), срок жизни.
2. `gifts/saling`: все фильтры, `count` ≤ 20, курсорная пагинация.
3. В amrkt: buy_gifts, sell_gifts (цены в nanoTON), get_inventory, return_gifts, balance (hard/soft), имитация TLS (curl_cffi `impersonate`), прокси.
4. Есть ли feed/история продаж, офферы, WebSocket.

Забираем: схему → `docs/MARKETS.md#mrkt`, клиент `markets/mrkt.py`, приём с `curl_cffi impersonate`.

### E. boostNT/Portals-API, Tonnel-API, MRKT-API — приоритет 2
Документация на русском. Свести с B/C/D, расхождения отметить в `docs/MARKETS.md`.

### F. kloveren/morgan-gift-plugins — приоритет 2
https://github.com/kloveren/morgan-gift-plugins

Изучить:
1. `gift-price-compare`: как сопоставляются одни и те же коллекции на 6 площадках (маппинг названий, алиасы), формула спреда.
2. `giftstat`: публичный агрегатор флоров — эндпоинты, что отдаёт, можно ли использовать как резервный источник.
3. `whale_tracker`: классификация держателей (Diamond Hands / Flipper / Accumulator) — пригодится для аналитики позже.
4. Плагин GetGems: on-chain покупка/листинг (на будущее, не MVP).

Забираем: таблицу алиасов коллекций → `pricing/aliases.py`; формулу арбитражного спреда; Giftstat как резервный источник флоров.

### G. bohd4nx/gifts-buyer — приоритет 3
https://github.com/bohd4nx/gifts-buyer

Изучить: как через MTProto получают список подарков магазина (`payments.getStarGifts`), формат `GIFT_RANGES`, приоритизация по редкости, контроль баланса звёзд.
Забираем: (не MVP) модуль «новые подарки в магазине» + формат описания правил как идею для пресетов.

### H. maxktz/telegram-gifts-radar и bohd4nx/gifts-tracker — приоритет 3
Изучить: частоту опроса, как определяют новые подарки и улучшения, схему БД (Prisma).
Забираем: идею уведомлений «вышел новый подарок / открыли улучшение».

Из README извлечь только идеи (в отчёт, без кода):
1. Кластерный флор с уровнями доверия high/med/low и запасной вариант (медиана 3 дешёвых, флор модели → символа → коллекции).

4. Режимы `auto/confirm/watch` и правило «если дешевле на другом маркете — спросить».
5. Команда `/doctor` (самопроверка конфига, сессии, часов, API).
6. Комиссии, которые они заявляют (Portals 0% покупка / 5% продажа / 0.1 TON вывод; Tonnel +10% к покупке) — пометить как **непроверенные**, проверить на практике.

Забираем: всё перечисленное как требования → `execution/`, `pricing/`, `bot/`.
