## Что делает (2–3 предложения)

По README: self-hosted снайпер подарков на MRKT. Опрашивает `/gifts/saling`, строит кластерный флор с доверием, считает прибыль после комиссии продажи, сверяется с оценкой Telegram и флорами Portals/Tonnel, шлёт карточки и покупает в ограниченном живом режиме. По умолчанию — практика.

## Как устроено (по README, не проверено)

- **Источник данных:** polling каждые 2 с; правила группируются по фильтру, на группу — запрос «самые дешёвые» и «самые новые» (`SCAN_NEWEST`); свои листинги исключаются; флоры коллекций из `/gifts/collections` кэшируются на `FLOOR_CACHE_TTL` (60 с). Бэкофф на 429 с учётом `Retry-After`; уведомление после 3 ошибок подряд.
- **Авторизация:** Telethon-сессия открывает Mini App @mrkt (`RequestAppWebView`, short name `app` — не подтверждено; запасной путь `RequestWebView` с `MRKT_WEBAPP_URL`), `initData` → токен MRKT через `/auth`. Можно задать `MRKT_TOKEN` вручную до его истечения. Повторная авторизация на 401/403, на 404 от известных эндпоинтов — не чаще раза в минуту (автор не знает, чем отвечает протухший токен: 404 или 401).
- **Модель данных:** цена `salePrice` в nanoTON, `salePriceWithoutFee` (из него выводится комиссия продажи по коллекции), `number`, редкость `modelRarityPerMille` / `backdropRarityPerMille` / `symbolRarityPerMille`, признаки lucky-buy (`lucky*`), премаркет; `floorPriceNanoTONsByBackdropModel` в объекте подарка (не используется). Поле времени листинга — догадки `listedAt` / `saleDate` / `updatedAt`.
- **Покупка:** `POST /gifts/buy`; ожидается непустой список `{userGift, price}`, всё остальное — «unknown». Продажи нет.
- **Хранение:** SQLite, `data/events.jsonl`, обменный файл `data/floors_mrkt.json`.

## Идеи по пунктам задания I (только идеи)

### 1. Кластерный флор, доверие, запасной вариант
- Кластер: самая низкая цена с ≥2 другими в пределах +10% выше; доверие `high/med/low` по числу сопоставимых; без кластера ≥3 — всегда `low`, так что две приманки не пройдут дефолтный `med`. Скачок >25%/ч понижает уровень.
- Запасной вариант (в этой версии): **флор коллекции** из `/gifts/collections`. Флор по модели/фону (`floorPriceNanoTONsByBackdropModel`) — в планах.
- Ловушки: lucky-buy билеты (`TRAP_LUCKY`), неизвестная единица цены; премаркет — как блокировка, пропуск, если правило не допускает; цена <25% флора не покупается автоматически.

### 2. Оценка Telegram (`payments.getUniqueStarGiftValueInfo`)
- Берутся average, last sale, listed count. Цена выше **и** средней, **и** последней продажи на тонком флоре → спросить. «Same type» в документации не определён — трактуется как контекст коллекции.
- Сверка с официальной документацией MTProto не выполнялась (сеть запрещена). Перечень полей по памяти модели и пометку «не проверено» см. в `docs/research/OnyxTarantulaLoop__portals-gifts-autobuy-bot.md`, п. 2.

### 3. Предохранители
- `DRY_RUN=true` — жёсткий замок; live = `DRY_RUN=false` + `/dry off`; одноразовая кнопка «Go live for 24 h» (10 мин, только если все правила `ready`) или `/dry off confirm`. Повторный `DRY_RUN=true` навсегда отменяет открытое окно. Свежая БД стартует в практике даже при `DRY_RUN=false`.
- Live-окно `LIVE_ARM_HOURS=24`.
- Лимиты на all-in под одним локом: `MAX_PRICE_TON=10`, `DAILY_BUDGET_TON=50` (скользящие 24 ч), `MAX_BUYS_PER_HOUR=3`, `CONFIRM_ABOVE_TON` (0 = половина max). NaN/inf → ошибка конфига. `/preset` не выше `.env` (но переход со строгого пресета на мягкий поднимает лимиты обратно до `.env`).
- Брейкеры: обвал флора > `CRASH_PCT`/ч, `LOSS_STREAK_N` убытков подряд → практика, расхождение баланса, `AUTO_PAUSE_ERRORS`.
- `/panic` + `/resume` с одноразовым подтверждением; кнопки, выданные до последней остановки, не работают.
- **«Результат неизвестен»:** каждая живая покупка пишется `unknown` до запроса; таймаут/сеть/5xx/неожиданный ответ — остаётся `unknown` и считается в лимитах. Непосредственно перед запросом правило перечитывается: отключено / на паузе / не `auto` / max снижен — не покупать.
- Shadow-правила; практические карточки остаются практическими.

### 4. Режимы и «дешевле на другом маркете»
- `auto` / `confirm` / `watch` на правило. `auto` всё равно спрашивает при «слишком хорошо», блокировке, **дешевле на другом маркете** (Portals/Tonnel), цене выше оценки Telegram на тонком флоре, стоимости > `CONFIRM_ABOVE_TON`. Бюджет второго мнения 3 с на цикл.
- Флоры других маркетов: локальные файлы `PEER_FLOOR_FILES` и опционально публичный эндпоинт коллекций Portals (`PEER_PORTALS_PUBLIC`).
- Near-miss карточки (≤5%, ≤3/ч), кнопки живут 24 ч; «Raise max» не снижает уже поднятый max.

### 5. `/doctor`
Конфиг, Telegram-сессия, 2FA, права файла сессии, авторизация MRKT, доступность, часы, БД, комиссии, лимиты; подсказка на каждую ошибку; exit code 1.

### 6. Комиссии — **заявлено, не проверено**

- Portals (для пиров): 0% покупка, 5% продажа, 0.1 TON вывод.
