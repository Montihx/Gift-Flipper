## Что делает

Неофициальная русскоязычная документация по REST API маркета Portals (NFT-подарки Telegram). Описывает два GET-эндпоинта (поиск подарков и поиск коллекций для получения ID), параметры фильтров и сортировки, а также получение заголовка авторизации `tma ...` через Pyrogram или DevTools. Покупка, продажа, баланс, офферы и комиссии в README не описаны.

## Как устроено

- **Base URL:** `https://portal-market.com`, пути начинаются с `/api`. Отдельным пунктом в README не выделен, виден из примеров URL.
- **Источник данных / эндпоинты (только то, что есть в README):**

| # | Метод | Путь | Назначение |
|---|---|---|---|
| 1 | GET | `/api/nfts/search` | Поиск подарков. Пример: `/api/nfts/search?offset=0&limit=20&sort_by=price+desc&status=listed`. В коде ответ читается из ключа `results`. |
| 2 | GET | `/api/collections?search={name}&limit=10` | Поиск коллекции по названию, чтобы узнать её ID. ID берётся из `['collections'][0]['id']`. |

- **Параметры `/api/nfts/search`:**

| Параметр | Тип / значения по README | Описание |
|---|---|---|
| `collection_ids` | строка, ID через запятую | Фильтр по коллекциям |
| `filter_by_models` | строка, через запятую | Фильтр по моделям |
| `filter_by_backdrops` | строка, через запятую | Фильтр по фонам |
| `external_collection_number` | число | Поиск по вхождению числа в номер подарка |
| `exclude_bundled` | True/False | Исключить подарки из бандлов |
| `premarket_status` | `all` / `only_premarket` / `without_premarket` | Премаркет-статус |
| `min_price`, `max_price` | тип не указан | Границы цены (единицы и формат не описаны) |
| `limit` | число, максимум 100 | Размер страницы |
| `offset` | число | С какого элемента начинать |
| `status` | `listed` / `unlisted`; без параметра возвращаются все | Статус листинга |
| `sort_by` | `поле desc` или `поле asc` (в URL `price+desc`) | Сортировка |

- **Значения `sort_by`:** `listed_at` (только `desc`), `price`, `external_collection_number`, `model_rarity`.
- **Пагинация:** `offset` + `limit` (limit ≤ 100). Курсора, общего счётчика или признака «последняя страница» в README нет.
- **Ответ:** описаны только ключи верхнего уровня `results` (поиск) и `collections` (коллекции). Полей объекта подарка (id, номер, модель, фон, цена и т.д.) в README нет. Не придумываем.
- **Частота / WebSocket:** в README не описаны. Лимиты запросов не указаны.
- **Авторизация:**
  - Заголовок `Authorization: tma {init_data}`. `init_data` берётся из параметра `tgWebAppData` URL веб-вью (код: `token = f'tma {init_data}'`).
  - Способ 1 (Pyrogram): `client.get_users('portals')`, `resolve_peer('portals')`, затем `RequestAppWebView(peer=peer, app=InputBotAppShortName(bot_id=<InputUser>, short_name='market'), platform="android")`. Из `web_view.url` вырезается часть между `tgWebAppData=` и `&tgWebAppVersion`, затем `unquote`. `start_param` не упомянут.
  - Способ 2 (вручную): веб-версия Telegram, DevTools, Network, любой GET к `portal-market.com`, скопировать `Authorization` из Request Headers.
  - Срок жизни: автор пишет, что неизвестен, но «точно более суток». Точной цифры нет.
- **Модель данных подарка:** в README не описана.

- **Комиссии:** нет (README о них не говорит). Статус «заявлено/проверено»: ничего не заявлено, ничего не проверено.
