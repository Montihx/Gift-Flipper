## Что делает (по зеркалу старой версии)

Юзербот автоматически отправляет звёздные подарки указанным пользователям Telegram. Умеет лимитированные и нелимитированные подарки, управляется конфигом. К флипу на маркетах прямого отношения не имеет.

## Как устроено
- Источник данных: по зеркалу, опрос с интервалом `CHECK_INTERVAL` (по умолчанию 10 с, рекомендуется не меньше 10). Пользователь `get_star_gifts` в Pyrogram, подтверждено только по строке из раздела Troubleshooting (ошибка `Client has no attribute get_star_gifts` при старом Pyrogram). Что внутри это `payments.getStarGifts`, я не проверял, это предположение. Разбора кода нет.
- Формат `GIFT_RANGES`: в зеркале НЕТ. Там есть `MAX_GIFT_PRICE` (по умолчанию 100), `GIFT_IDS` (фильтр по ID), `GIFT_QUANTITY` (по умолчанию 1), `PURCHASE_NON_LIMITED_GIFTS`, `USER_ID`. Формат диапазонов, если он есть в актуальной версии, неизвестен.
- Приоритизация по редкости: в зеркале не найдена.
- Контроль баланса звёзд: в зеркале не найден (есть только потолок цены `MAX_GIFT_PRICE`). Проверки остатка звёзд перед покупкой не видел.
- `payments.getUniqueStarGiftValueInfo`: в прочитанном тексте не встречается. Использование в коде неизвестно.
- Авторизация: сессия Pyrogram (`data/account`), `API_ID`/`API_HASH`.
- Хранение состояния: `data/history.json` (история отправленных подарков).
- Уведомления: пост в канал по `NOTIFICATION_CHAT_ID`.
- Остальные пункты шаблона (модель данных, оценка, комиссии, покупка, предохранители) не применимы или не прочитаны.
