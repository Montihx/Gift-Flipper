## Что делает (2–3 предложения)

По README: self-hosted снайпер подарков Telegram на маркете Portals. Опрашивает поиск Portals, считает «честный» кластерный флор с уровнем доверия, прибыль после комиссий, сверяется с оценкой Telegram и флорами MRKT/Tonnel, шлёт карточку сделки в админ-бота и (в живом режиме) покупает. По умолчанию — практика (dry-run), живой режим ограничен 24 ч.

## Как устроено (по README, не проверено)

- **Источник данных:** polling раз в 2 с (`POLL_INTERVAL`): один запрос «самые новые» по всем коллекциям правил + один «самые дешёвые» на каждый уникальный фильтр правила. Флоры коллекций/атрибутов кэшируются на `FLOORS_TTL` (60 с). Бандлы исключаются прямо в поиске.
- **Авторизация:** поиск и флоры Portals — публичные (без авторизации). Для покупки и баланса — Telethon-сессия, через которую открывается Mini App @portals и берётся `initData` (`RequestAppWebView`, short name `market`; запасной путь `RequestWebView` с `PORTALS_WEBAPP_URL`). Альтернатива — вручную вставленный `PORTALS_INIT_DATA` (без самообновления). `INIT_DATA_TTL=1800` назван «догадкой»; обновление при любом 401/403.
- **Модель данных:** Listing (id, цена-строка, коллекция, модель, фон, символ с редкостью, `unlocks_at`, признак бандла), флоры коллекций и атрибутов, slug `t.me/nft/...`.
- **Оценка/флор:** см. п. 1 ниже.
- **Комиссии:** см. п. 6 ниже.
- **Покупка:** `POST /nfts` с телом `{"nft_details":[{"id": "<nft id>", "price": "<строка цены как в API>"}]}`. Ответ неизвестен; «куплено» только при 2xx с объектом без `error`/`detail`/`message`, иначе «результат неизвестен». Продажи нет («It never sells»).
- **Предохранители:** см. п. 3.
- **Уведомления / UI:** aiogram-бот только для `ADMIN_IDS`; карточки с кнопками Buy / Skip / Mute 24h / Why? / Open gift / Open Portals; near-miss карточки; дайджест; `/why` объясняет решение по коду причины.
- **Хранение:** SQLite (`seen`, `purchases`, `rules`, `settings`, `floor_snapshots`, `observations`, `decisions`, `pending`, `mutes`, `marks`), `data/events.jsonl`, файл флоров `data/floors_portals.json` для обмена с ботами других маркетов.

## Идеи по пунктам задания I (только идеи, без кода)

### 1. Кластерный флор, уровни доверия, запасной вариант
- Кластерный флор = самая низкая цена, у которой есть ещё **≥2 предложения в пределах +10%** выше неё (кластер ≥3). Защищает от продавца с двумя приманками, который подделывает «второй по дешевизне» флор.
- Уровень доверия `high` / `med` / `low` — по числу сопоставимых объявлений за флором. Без кластера ≥3 — всегда `low`. Правило по умолчанию `min_confidence=med` не покупает на `low`.
- Понижение на один уровень, если флор сдвинулся **>25% за час** (`FLOOR_JUMP_PCT`).
- Запасной вариант: нет кластера → **медиана трёх самых дешёвых других** объявлений, метка `thin`, доверие `low`; нет сопоставимых → флор **модели → символа → коллекции**.
- Флоры фонов из `/collections/filters` не используются: выглядят общими по маркету, а не по коллекции.
- Параметры (имена из README): `CLUSTER_K`, `CLUSTER_BAND_PCT`, `MIN_COMPARABLES_COLLECTION`, `MIN_COMPARABLES_ATTR`, `TOO_GOOD_PCT`.
- Признание автора: продавец с ≥3 приманками всё равно сформирует кластер — оставлять запас в `max` или `conf=high`.
- Фильтр ловушек: бандлы блокируются; подарок с `unlocks_at` в будущем — пропуск, если правило не допускает блокировку (и даже тогда — спросить); цена <25% флора никогда не покупается автоматически; неизвестная единица цены — отказ.

### 2. Оценка Telegram (`payments.getUniqueStarGiftValueInfo`)
- По README: для конкретного уникального подарка берутся «average, last sale, listed count» (плюс floor), кэш `TG_VALUE_TTL`, ограничение `TG_VALUE_MAX_PER_MIN`, гард `TG_VALUE_GUARD`. Правило: если цена выше **и** средней, **и** последней продажи по Telegram при флоре `low` — не покупать автоматически, а спросить.
- Автор отмечает: в документации API не определено, что значит «same type», поэтому floor/average/listed count трактуются как контекст коллекции.
- Сверка с документацией MTProto выполнена на Этапе 0 отдельно (п. 0.4 плана): поля и ограничения — в `docs/research/SUMMARY.md` §3 (источник: core.telegram.org через результаты поиска и зеркала схемы). В этом отчёте поля не перечисляются, чтобы не дублировать непроверенный пересказ.

### 3. Модель предохранителей
- `DRY_RUN=true` по умолчанию — жёсткий замок: пока `true`, никакая команда или сохранённая настройка не включит живой режим. Для живого режима нужно `DRY_RUN=false` в `.env` **и** `/dry off` в боте.
- `/dry off` сначала показывает отчёт практики; одноразовая кнопка «Go live for 24 h» (живёт 10 мин) появляется, только если все правила в статусе `ready`; иначе — явное `/dry off confirm`.
- Живой режим на `LIVE_ARM_HOURS=24`, затем сам возвращается в практику. После рестарта — практика, если окно не открыто; отсутствующее/битое/слишком длинное окно читается как практика.
- Лимиты на all-in стоимость, под одним локом, для автопокупок и тапов: `MAX_PRICE_TON=10`, `DAILY_BUDGET_TON=30` (скользящие 24 ч), `MAX_BUYS_PER_HOUR=3`, `CONFIRM_ABOVE_TON` (0 = половина действующего max). Практика и живой режим считаются раздельно. `nan`/`inf` в конфиге запрещены; проверка, встретившая NaN, блокирует покупку (fail closed). `/preset careful|normal|bold` никогда не поднимает выше `.env`.
- Брейкеры: флор правила упал > `CRASH_PCT` за час → пауза правила (`CRASH_PAUSE_MIN`); `LOSS_STREAK_N` убыточных живых покупок подряд → назад в практику; баланс (доступный + замороженный) упал больше собственных трат + `BALANCE_TOLERANCE_TON` → пауза; `AUTO_PAUSE_ERRORS` неудачных покупок подряд → пауза. Также `STALE_DATA_SEC`, `HOT_WALLET_WARN_X`.
- `/panic`: пауза, принудительная практика, аннулирует кнопку go-live, протухают все ожидающие карточки; покупка в процессе отказывает на последней проверке. Снятие — `/resume` с одноразовым подтверждением (10 мин), затем новый `/dry off`. Кнопка resume, выданная до последней остановки, не работает.
- Единственная функция траты с одним локом: перечитывает переключатели и правило, проверяет лимиты по свежим суммам, перед `POST /nfts` ещё раз проверяет баланс и все переключатели.
- **«Результат неизвестен»:** живая покупка записывается как `unknown` **до** отправки запроса; таймаут, сетевая ошибка, обрыв — остаётся `unknown` и **учитывается в лимитах**; только явный успех превращает её в покупку.
- Shadow-правила: новые правила (из бота и `rules.json`) работают только в практике даже в живом режиме, пока их не повысят `/promote`.
- Карточка помнит режим, в котором отправлена: тап по PRACTICE-карточке — только практическая покупка; включение live протухает все практические карточки.

### 4. Режимы и «дешевле на другом маркете»
- Режим на правило: `auto` (по умолчанию), `confirm`, `watch`.
- Даже в `auto` бот **спрашивает**, если: цена «слишком хороша», подарок заблокирован, **дешевле на другом маркете** (`CHEAPER_ELSEWHERE_PCT`), цена выше средней и последней продажи Telegram при `low`-флоре, или стоимость > `CONFIRM_ABOVE_TON`.
- Флоры других маркетов берутся из локальных JSON-файлов, которые пишут боты для MRKT/Tonnel (`PEER_FLOOR_FILES`), без сети; `/compare` показывает один подарок на всех маркетах all-in и net. Второе мнение укладывается в бюджет 3 с на цикл и не блокирует решение.
- Перед покупкой по тапу цена перепроверяется; карточки живут 90 с; двойной тап безопасен.
- Near-miss: тихая карточка, когда ровно одна проверка не прошла на ≤5%, с кнопкой «Raise max» (не больше 3 в час).

### 5. `/doctor`
Проверяет: конфиг бота, Telegram-сессию, 2FA, права файла сессии (600), авторизацию Portals, доступность API, расхождение часов, движок, правила, комиссии, пиров, БД и лимиты; для каждого проваленного пункта — подсказка, как исправить; код выхода 1 при любой ошибке. Не печатает телефон и секреты.

### 6. Заявленные комиссии — **заявлено, не проверено**
- Portals: покупка **0%**, продажа **5%**, вывод **0.1 TON**; коллекции с флагом `zero_commission` — продажа 0%. Сам автор помечает их как допущения (`FEES_VERIFIED=false`) и не знает, добавляется ли комиссия к цене листинга.
- Для пиров (из схемы файла флоров): MRKT и Tonnel — свои комиссии в каждом файле.

### Прочие идеи (не из списка, но полезные)
- Дедуп по ключу `id:price`: дешёвый перелист — новое событие.
- Журнал решений: каждая оценка (включая пропуски) в таблицу `decisions` и JSONL с кодами причин (`BELOW_FLOOR`, `FEW_COMPS`, `FEES_EAT_PROFIT`, `PRICE_ABOVE_MAX`, `LIMIT_DAILY_BUDGET`, `LIMIT_HOURLY`, `CHEAPER_ELSEWHERE`, `TRAP_BUNDLE`, `LOCKED`, `TOO_GOOD`, `ABOVE_TG_VALUE` и др.) + `/why`.
- `/scoreboard` практики: «что купил бы / сколько стоит сейчас / P&L» и счётчик «гонок, вероятно проигранных» (листинг исчез за 2 мин). Вердикт на правило `ready / losing / not enough data` — условие для go-live.
- Формат обменного файла флоров между ботами (`schema`, `market`, `ts`, `fees`, `collections{key:{name, floor, n, models}}`), ключи нормализованы через таблицу алиасов.

## Для MARKETS.md

Всё ниже — **из README подозрительного репо, не проверено**; использовать только как гипотезы для сверки с portalsmp/boostNT.

- Portals: хост API `portal-market.com` (без «s»); `portals-market.com` не резолвится (из README).
- `GET /nfts/search` — публичный; сортировки `price asc`, `listed_at desc`; фильтр `collection_ids` (несколько сразу), фильтры модели, диапазон цен; `premarket_status=all`; `listed_at desc` возвращает новые, но не строго по порядку (из README).
- `GET /collections?limit=500` — 123 коллекции одним ответом, пагинации не замечено; `GET /collections/filters` (флоры фонов выглядят общими по маркету); `GET /collections/floors` (из README).
- `GET /users/wallets/` — 401 без авторизации; ожидается `{"balance": "...", "frozen_funds": "..."}` (из README, не проверено автором).
- `POST /nfts` — покупка, тело `{"nft_details":[{"id":"<nft id>","price":"<строка цены как в API>"}]}`; ответ неизвестен (из README).
- Лимиты: заголовок `x-ratelimit-limit: 2` на search, `12` на floors; 2.0 rps ловил 429, по умолчанию 1.5 rps; бэкофф с учётом `Retry-After` (из README).
- Авторизация: `initData` Mini App @portals через Telethon `RequestAppWebView`, short name `market` (не подтверждено); TTL `initData` ~1800 с — догадка; рефреш на 401/403 (из README).
- Поля: `zero_commission` у коллекции (0% продажи), `unlocks_at` (трактуется как «нельзя перепродать до»), цены в TON строкой (из README).
- Эндпоинт истории сделок требует авторизации (401 без неё) (из README).
- Комиссии: покупка 0%, продажа 5%, вывод 0.1 TON — **заявлено, не проверено**.
