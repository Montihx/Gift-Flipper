# AGENTS.md — Gift Flipper

Главный файл инструкций для любого ИИ-агента (Claude Code, Codex, Cursor и т.д.), который работает в этом репозитории. `CLAUDE.md` ссылается сюда. Если правила расходятся — прав этот файл.

## 1. Что это за проект

Gift Flipper — сервис для поиска и перепродажи (флипа) NFT-подарков Telegram на маркетах **Portals, MRKT, Tonnel**.

- **Mini App (TWA)** — основной интерфейс: лента сделок, карточка подарка, фильтры и пресеты, портфель, лимиты и режимы.
- **Бот** — только уведомления и действия в один тап: «Купить», «Пропустить», «Открыть в приложении», «Пауза», «Panic», итог дня. Никаких меню и настроек в боте.
- **Бэкенд** — воркеры маркетов, движок оценки, движок правил, исполнение покупок с предохранителями, API для Mini App.

Макет экранов: https://claude.ai/artifact/LA49kx9TAYP9dPkxmKEVCa

## 2. Стек (черновик, финал — в `docs/DECISIONS.md`)

| Слой | Выбор |
|---|---|
| Язык бэкенда | Python 3.12, asyncio |
| API | FastAPI + проверка Telegram `initData` (HMAC по токену бота) |
| Бот | aiogram 3 |
| Доступ к маркетам | свои клиенты на `aiohttp`/`curl_cffi`; авторизация через `initData`, полученный Telethon-сессией владельца |
| БД | PostgreSQL + SQLAlchemy 2 (async) + Alembic |
| Очередь/кэш | Redis (pub/sub для новых сделок, кэш флоров) |
| Mini App | React + Vite, JSX, `@telegram-apps/sdk`, цвета из `themeParams` Telegram |
| Тесты | pytest, pytest-asyncio, записанные ответы API (fixtures), MockClient для каждого маркета |
| CI | GitHub Actions: lint (ruff), типы (mypy, по возможности), тесты, сборка фронта |

## 4. Жёсткие правила безопасности

1. **Деньги.** Реальные покупки только через `execution.spend()`. Других путей к эндпоинтам покупки быть не должно. По умолчанию `DRY_RUN=true`. В тестах и CI реальные запросы к маркетам и покупки запрещены — только MockClient и фикстуры.
2. **Секреты.** Telethon-сессии, `initData`, токены маркетов, токен бота хранятся только в `.env`/секретах и в каталоге `data/` с правами 600. Никогда не коммитить, не логировать целиком, не отправлять во внешние сервисы. Логи маскируют токены.
3. **Чужой код.** Код из исследуемых репозиториев не запускать и не копировать в проект целиком. Брать идеи, описания эндпоинтов, алгоритмы — и переписывать. Особенно: никаких `.exe`, бинарников, обфусцированного кода, `pip install` из неизвестных репо. Список подозрительных репо — в `docs/REPO_ANALYSIS.md`.
4. **Лицензии.** Если переносится заметный фрагмент кода с лицензией MIT/Apache — указать источник в комментарии и в `docs/DECISIONS.md`. Код без лицензии не копировать.
5. **Лимиты API.** Каждый клиент маркета: throttle, backoff на 429/5xx, таймауты, jitter. Не долбить маркеты чаще, чем указано в `docs/MARKETS.md`.
6. **Необратимые действия** (покупка, выставление, вывод средств, миграции с удалением данных) — агент не выполняет на проде сам, только готовит и описывает.

## 5. Как работать агенту

- Перед задачей прочитать: этот файл → `docs/HANDOFF.md` → `docs/PLAN.md` (текущий этап) → связанные разделы `docs/MARKETS.md` и `docs/DECISIONS.md`.
- Ветка одна на весь проект, PR в `main` один (D-016). Маленькие коммиты, сообщения на русском или английском, в повелительном наклонении: `markets: add Portals search client`.
- Новый агент в новом чате начинает с `docs/HANDOFF.md`.
- Новая логика = тесты. Оценка и комиссии покрываются табличными тестами с конкретными числами.
- Деньги считать в **nanoTON (int)** внутри, в TON (Decimal) только на отображении. Никаких float для денег.
- Время — UTC, `datetime` с tz.
- Перед PR: `ruff check`, `ruff format --check`, `pytest`, `npm run build` в `webapp/` — всё зелёное.

## 6. Ведение документации (обязательно)

После каждой завершённой задачи агент обновляет:

| Что изменилось | Куда записать |
|---|---|
| Статус задачи/этапа | `docs/PLAN.md` — галочка, дата, ссылка на PR |
| Принято решение (выбор библиотеки, формула, отказ от фичи) | `docs/DECISIONS.md` — новая запись: контекст, решение, альтернативы, последствия |
| Узнали что-то об API маркета | `docs/MARKETS.md` |
| Изменения, видимые пользователю | `CHANGELOG.md` (раздел Unreleased) |
| Новые команды, переменные окружения, структура | этот файл и `.env.example` |

Документация обновляется в том же PR, что и код. PR без обновления документации, где оно нужно, — не готов.

## 7. Команды

```bash
# backend (Python 3.12, uv)
cd backend && uv sync --python 3.12
uv run pytest
uv run ruff check . && uv run ruff format --check .
uv run alembic upgrade head          # DATABASE_URL из .env
uv run alembic check                 # модели и миграции совпадают
uv run python -m app.engine --dry-run --once      # листинги из фикстур
uv run python -m app.engine --dry-run --plan      # список живых запросов для владельца
uv run python -m app.engine --dry-run --live --notify   # watch с пушами (LIVE_READS_APPROVED=yes)
uv run python -m app.bot                           # команды бота, итог дня
uv run python -m app.tools.login                   # вход Telethon (на ПК владельца)
uv run uvicorn app.api.main:app --port 8000        # API для Mini App

# webapp
cd webapp && npm ci && npm run dev
npm run build
```

## 8. Словарь

- **Флор (floor)** — минимальная надёжная цена для сопоставимых подарков (коллекция → модель → модель+фон).
- **Кластерный флор** — минимальная цена, рядом с которой (в пределах 10%) есть ещё ≥2 объявления.
- **All-in** — сколько реально платим с комиссией покупки. **Net** — что остаётся после перепродажи по флору минус комиссия продажи и вывода.
- **Режимы:** `watch` — только пуш; `confirm` — пуш с кнопкой «Купить»; `auto` — покупка сама в пределах лимитов.
- **Panic** — мгновенно перевести всё в `watch` и остановить исполнение.
